# EdgeNode — 엔진 · 엣지 에이전트 · 추론 워커 자리를 한 장의 compose 로

현장 장비 한 대에 **엔진**과 **엣지 에이전트**를 함께 띄우고, 카메라 영상을 보는 **추론 워커**가 들어갈 자리를 둔 예제다. 에이전트는 엔진으로 **나가는 방향으로만** 연결하고(들어오는 포트 없음) 워커와는 공유 볼륨 안의 유닉스 소켓 하나로 이야기한다.

```bash
cd samples/EdgeNode
echo "ADMIN_PIN=<관리자 PIN>" > .env
docker compose up -d engine                  # 1. 엔진부터
# 2. 관리 화면(http://localhost:8080/u-vision/) «노드» 탭에서 등록 토큰을 발급한다(한 번만 쓰이고 평문은 발급 직후에만 보인다)
echo "UVISION_REGISTRATION_TOKEN=<토큰>" >> .env
docker compose up -d                         # 3. 에이전트가 등록하고 이후에는 저장한 자격으로 돈다
```

«노드» 탭에 노드가 나타나면 시나리오를 **배정**한다(배정이 없는 노드는 빈 구성을 받는다). 토큰은 처음 한 번만 필요하고, 그 뒤에는 `.env` 에서 지워도 된다.

## 무엇이 들어 있나

| 서비스 | 하는 일 |
|---|---|
| `engine` | 게시 이미지 `ghcr.io/iyulab/u-vision`. 데이터는 `engine-data` 볼륨. `ADMIN_PIN` 필수(관리 동작을 지킨다). 판정원은 기본 `mock` — 실제 VLM 은 `VLM_PROVIDER` · `VLM_ENDPOINT` 등(README «엔진 서버로 띄우기»). |
| `socket-dir` | 한 번 돌고 끝나는 준비 단계 — 새 볼륨은 root 소유라 비루트 에이전트가 소켓 파일을 못 만든다. 디렉터리를 에이전트의 그룹(1654)에 넘긴다. |
| `edge-agent` | 게시 이미지 `ghcr.io/iyulab/u-vision-edge-agent`. 자격 · 마지막 구성 · 아직 도착하지 못한 사건(outbox)이 `edge-data` 볼륨에 남으므로 **이 볼륨을 지우지 않는다**. |
| `worker` (주석) | 추론 워커 자리. 이 저장소에는 소프트웨어 워커의 소스(`src/UVision.Edge.Worker`)와 `Dockerfile.edge-worker` 가 있지만 **이미지는 게시하지 않는다**(디코더로 쓰는 `ffmpeg` 배포본의 라이선스를 검토하기 전) — 로컬에서 지어 쓴다. Jetson 용 워커(하드웨어 디코드 · TensorRT)는 아직 없다. |

## 소켓 권한 — 왜 `0660` 과 그룹인가

에이전트가 여는 소켓 파일은 기본으로 **소유자만** 읽고 쓴다(`0600`). 워커가 다른 사용자로 도는 별도 컨테이너면 연결이 `Permission denied` 로 거절된다. 그래서 에이전트에 `UVISION_WORKER_SOCKET_MODE=0660` 을 주고, 워커에는 에이전트의 **그룹**(`1654`)을 준다(`user: "2000:1654"` 또는 `group_add: ["1654"]`). 같은 볼륨을 나누는 다른 컨테이너까지 열게 되는 `0666` 은 쓰지 않는다. 1654 는 .NET 기본 이미지의 앱 사용자 · 그룹이다.

## 워커가 지켜야 할 것

워커는 **보기만 한다**(디코드 · 검출 · 추적) — 판단은 에이전트가 시나리오의 규칙으로 한다. 워커는 에이전트가 듣는 소켓에 연결해 줄마다 JSON 객체 하나를 보낸다(줄 끝은 LF — 개행 문자 하나).

```json
{"v":1,"type":"tracks","source_id":"dock-1","seq":42,"t":"2026-11-04T09:00:00.123+00:00","tracks":[{"id":"7","class":"box","score":0.91,"box":[0.12,0.30,0.10,0.18]}]}
{"v":1,"type":"source_state","source_id":"dock-1","state":"no_signal","t":"2026-11-04T09:00:05Z"}
```

- `source_id` 는 **카메라 별칭**이다(시나리오의 `camera_ref`). 실제 카메라 주소(비밀번호가 들어갈 수 있다)는 시나리오에 적지 않고 노드 안에서만 풀린다.
- `t` 는 프레임이 찍힌 시각이고 **시간대가 있는 ISO 8601** 이어야 한다(없으면 그 줄을 버린다). `box` 는 `[x, y, w, h]` 이고 0~1(왼쪽 위 원점), 한 프레임의 트랙은 2000 개 이하, 한 줄은 1 MiB 이하다. `seq` 는 선택(소스별 단조 증가). `state` 는 `ok` · `no_signal` · `degraded`.
- 모르는 판 · 모르는 `type` · 깨진 JSON · 한도를 넘은 줄은 **그 줄만 버리고** 연결은 끊지 않는다(버린 수와 마지막 사유는 «노드» 탭에 보인다). 워커는 하나만 붙는다 — 새 연결이 오면 옛 연결을 대신한다. 연결이 끝나면 알려진 카메라는 모두 «소실» 이 된다.

## 이 예제가 보증하지 않는 것

- 게시된 추론 워커 이미지가 없다 — 이 예제만으로는 노드가 «연결되어 있다» 는 것까지 보인다(사건을 만들어 넣어 주는 것은 워커다). 소프트웨어 워커를 로컬에서 지어 붙이는 방법은 `server/Dockerfile.edge-worker` 머리말에 있다.
- 태블릿 카메라는 **HTTPS** 에서만 열린다. 이 compose 는 평문 `8080` 만 연다 — 현장에서는 앞단에 TLS 를 둔다([`samples/SameOriginMount`](../SameOriginMount) 의 리버스 프록시 참고). 엔진 주소가 같은 기계 밖의 `http://` 이면 등록 토큰과 노드 자격이 평문으로 오간다.
- arm64(Jetson 등)에서의 실행은 이 예제로 확인하지 않았다(이미지는 amd64 · arm64 를 함께 게시한다).
